zeropi.display

A Pi Zero e-ink display for live Claude Code usage

A gauge of consumption against the rolling five-hour and seven-day limit windows, backed by a history of daily cost — read from the local Claude Code logs, no API key. Your Linux machine reads the usage and pushes it over Bluetooth Low Energy to a Raspberry Pi Zero with a Waveshare e-ink HAT.

How it works

Desktop
Parses and prices the JSONL logs, reads the live rate-limit snapshot, pushes over BLE
Pi
Stores daily Readings, holds the live Gauge, answers every write with an Ack
Panel
250×122, 1-bit, full refresh at most every 300 s

The Pi never reads logs or computes anything, and holds no wall clock: everything time-shaped arrives as a duration. It shows the Historic View — recent active days with their cost — at rest, and the Gauge frame while a fresh live Gauge is held. An expired Gauge is never drawn.

What crosses the link

Four Payload kinds on one write characteristic, each ≤ 512 bytes.

KindOn the Pi
DailyStored as a Reading — the history the panel draws
GaugeHeld in memory; expires 300 s after the snapshot was taken
SettingsPersisted and applied live; re-asserted on every connection
Commandstatus, redraw or wipe, answered in the Ack

Is it working?

A resident systemd --user service does the pushing. desktop/cli.py checks on it and manages it.

  ✓  Working.

  Pi        replied in 0.1s, up 1d 6h

  Coupled    ✓  replied, not wiped
  Image      ✓  schema 1
  Panel      ✓  historic frame, drew 2m 23s ago
  Readings   ✓  15
  Coverage   ✓  2026-09-04
  Restarted  ✓  up 1d 6h

status compares what the Desktop sent with what the Pi reports and answers working, not working, can't tell or not paired — a powered-off Pi is never reported as broken. Alongside it: pair, push, redraw, wipe, config and restart.

Install

On the Pi — no clone needed:

curl -fsSL https://raw.githubusercontent.com/peterderkoala/zeropi.display/dev/install.sh | bash -s -- pi

On the Desktop, from a clone:

uv venv .venv && uv pip install -r desktop/requirements.txt
.venv/bin/python desktop/cli.py pair

The live Gauge needs claude-hud writing its rate-limit snapshot. The README covers the resident service and the rest of the setup.

Verified on real hardware

Raspberry Pi Zero 2 W · Waveshare 2.13″ e-Paper HAT V4 · BlueZ 5.82

  • The BLE link — single-write Payloads and Acks at a 517-byte MTU
  • Real usage data from the Claude Code logs, pushed unattended
  • Unattended provisioning that survives reboots and bluetoothd restarts
  • Every frame drawn and read on real glass
  • The management surface end to end: Settings, all three Commands, both unreachable cases
